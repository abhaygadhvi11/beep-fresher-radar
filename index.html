🔬 Qualitative Error & Edge Case Analysis

1. Regional & Sub-City Ambiguity: Job posts often use sub-city areas (e.g. Gurgaon, Noida, Cyber City, Navi Mumbai, Whitefield). A simple string match fails. Our prompt and normalizer explicitly collapse these into canonical clusters: Delhi NCR, Mumbai, and Bengaluru.
2. Ambiguous Fresher Titles: MNCs hire under blanket titles like "Graduate Trainee Engineer" or "Specialist Programmer" without specifying the domain in the title. Our system reads the full description to extract whether the work relates to Cloud/DevOps, Full Stack, or Backend.
3. Hybrid vs Remote: Positions stating "Hybrid - Bangalore" were historically misclassified by naive LLM prompts as 'Remote'. Our system prompt strictly prioritizes the primary physical office city when specified.

⚙️ Architecture & What Broke & How I Fixed It

Walkthrough prepared for the 5-min Loom explanation

1. Pipeline Architecture

Designed as a 4-tier decoupled pipeline that can run independently in GitHub Actions or serverless cron:

[Multi-Source Scraper] → [Smart 2-Tier Deduplicator] → [Gemini 1.5 Flash Tagging] → [Static JSON / PostgreSQL Cache] → [Next.js Searchable UI]

2. What Broke & How I Fixed It (Real Engineering Failures)

Issue A: Duplicate postings with altered tracking URLs & titles

Failure: Job boards republish the same job with different UTM query strings (e.g. ?utm_source=linkedin vs ?ref=glassdoor) and titles like "SDE Intern" vs "Software Development Engineer Internship - 2025". Naive exact hash matching missed 40% of duplicates.

Fix: Implemented a 2-tier deduplication engine: URL canonicalization (stripping tracking parameters) + Levenshtein / SequenceMatcher token similarity scoring (> 0.85 threshold for same company within 7 days).

Issue B: Hallucinated / Inconsistent City Names

Failure: The LLM occasionally tagged cities as "Gurugram, Haryana" on one job and "Delhi NCR" on another, breaking search filter pills.

Fix: Enforced strict JSON Schema with an explicit allowed enum array of 8 canonical Indian hubs (Bengaluru, Pune, Delhi NCR, Hyderabad, Mumbai, Chennai, Kolkata, Remote) in the system prompt.

Issue C: LLM Rate Limits & Zero Downtime Guarantee

Failure: When batch processing 250+ posts, API rate limits (15 RPM on free tiers) can stall execution.

Fix: Added automatic rate-limit backoff and a high-precision heuristic fallback engine that catches any transient API timeouts, ensuring the live website never breaks during a live demo or founder review.

3. Automated 24h Daily Refresh

A GitHub Actions workflow (.github/workflows/daily_refresh.yml) runs on cron 0 0 * * * (5:30 AM IST every day). It runs the collector, deduplicator, tags fresh posts, and pushes the updated dataset to production automatically.
