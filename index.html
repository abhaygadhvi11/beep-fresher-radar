🔬 Qualitative Error & Edge Case Analysis

3. Direct Deep-Links: Every post leads directly to that specific opening's ATS application form (Greenhouse, Lever, SmartRecruiters, Ashby) rather than generic corporate landing pages.

⚙️ Architecture & What Broke & How I Fixed It

Walkthrough prepared for the 5-min Loom founder explanation

1. Pipeline Architecture

Designed as a 4-tier decoupled pipeline that runs independently in GitHub Actions:

[Public ATS Feeds] → [2-Tier Deduplicator] → [Gemini 2.5 Flash Structured Tagging] → [Production Cache] → [EventBeep Styled UI]

2. What Broke & How I Fixed It (Real Engineering Failures)

Issue 1: Deduplication Breakdown (Tracking URLs & Fuzzy Title Variants)

Failure: Job boards republish identical openings with altered UTM tracking parameters (?utm_source=linkedin) and mutated titles ("SDE Intern (2025)" vs "Software Development Engineer - Internship"). Naive exact hash matching missed over 30% of duplicates, while naive company hashing purged 214 valid jobs.

Fix: Built a 2-tier deduplication engine in pipeline/deduplicator.py: URL canonicalization (stripping tracking query params and hashes) + normalized company/title token similarity scoring (SequenceMatcher ≥ 0.85 threshold), retaining distinct roles per company while eliminating duplicates.

Issue 2: Inconsistent City Clustering & Fragmented Filter Chips

Failure: Raw job locations referenced sub-regions ("Gurgaon, Haryana", "Whitefield", "Navi Mumbai", "DLF Cyber City"). An unconstrained LLM prompt generated 15+ fragmented cities ("Gurugram", "Noida", "NCR", "Delhi/NCR"), breaking frontend UI filters.

Fix: Enforced strict structured JSON schema with an explicit enum of 8 canonical Indian hubs (Bengaluru, Pune, Delhi NCR, Hyderabad, Mumbai, Chennai, Kolkata, Remote) and explicit geographic routing rules in the system prompt.

Issue 3: Generic Career Site Redirection & LinkedIn Keyword Search Mismatch

Failure: Generic career roots (careers.swiggy.com/#/careers) dumped students on homepages forcing them to re-search. In addition, an experimental secondary LinkedIn search button queried raw titles like *Associate - Project Management support Bosch which returned completely unrelated sponsored jobs (Mastercard, Regnology).

Fix: Ingested 240+ direct, deep ATS application URLs from Lever, Greenhouse, SmartRecruiters, Ashby, and Workable linking straight to the active resume submission form. Replaced fragile external search scrapers with one authoritative Apply on [Company] Portal → button.

Issue 4: Raw Feed Noise & Non-Student Roles (Factory/SAP/Logistics)

Failure: Raw scraped feeds contained legacy enterprise and factory roles like *Associate - Project Management support (SAP invoice processing), Physical Logistics, and Calibration Specialist that were irrelevant for college students or freshers (0-1 YOE).

Fix: In pipeline/collectors/deep_ats_collector.py, added strict exclusion regex patterns filtering out logistics, warehouse, SAP support, and factory roles. Re-sorted the dataset so verified tech internships (FamPay, HackerRank, Databricks, GitLab) appear first.

Issue 5: Search Multi-Keyword Indexing & Role Attribute Omission

Failure: Typing "Backend Engineer" in search only returned 2 jobs despite 114 backend roles, because the filter only checked title and skills (omitting job.role and job.city) with rigid exact substring matching.

Fix: Expanded the search index to include job.role, job.city, job.location, and job.job_type with tokenized multi-term matching (terms.every(...)). Now typing "Backend Engineer" instantly returns all 114 jobs. Added a 1-click × clear button.

Issue 6: LLM Rate Limits & Live Demo Failure Prevention

Failure: Rapid batch tagging of 200+ jobs via LLM API endpoints triggered 429 Too Many Requests or transient timeout exceptions, risking pipeline failure during live evaluations.

Fix: Built a dual-mode architecture in pipeline/llm_tagger.py: every API call is wrapped in a robust try/except handler that seamlessly falls back to our high-precision rule-based semantic regex tagger with zero downtime.

Issue 7: GitHub Secret Scanning Push Protection Remediation

Failure: GitHub blocked git push with error GH013: Push cannot contain secrets due to an API key committed in a test script.

Fix: Performed a git soft reset, permanently purged the key from git history, migrated all credentials strictly to .env (gitignored), and pushed cleanly.

Issue 8: EventBeep Native Visual Identity Alignment

Failure: Default dark mode templates felt generic and disconnected from EventBeep's real college product aesthetic.

Fix: Overhauled the UI to mirror EventBeep's official visual identity: warm ivory background (#FFFDF2), midnight navy (#002032), royal blue (#4C63DB), butter yellow (#FFE88A), official vector logo (beepLogo.svg), and Patrick Hand college badges.

3. Automated 24h Daily Refresh

A GitHub Actions workflow (.github/workflows/daily_refresh.yml) runs on cron 0 0 * * * (5:30 AM IST every day). It re-runs the pipeline, tags fresh jobs, and commits to production automatically.
